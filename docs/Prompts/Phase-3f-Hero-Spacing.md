## Goal

Reduce the Home page hero's vertical whitespace substantially, without shrinking any of its content (logo, headline, description, button stay the same size). The hero should become **content-driven** — its height is a function of its own padding and content, not the viewport — landing at approximately **650–700px of total dark area (header + hero combined) on a 1440×900-class desktop viewport.**

---

## Project Context

Current hero (`src/pages/index.astro`):

```astro
<section style={`background-color: var(--color-brand-charcoal);`} class="px-6 py-24 sm:py-32">
  <div class="mx-auto flex max-w-[var(--content-max-width)] flex-col items-center gap-6 text-center">
    <Image src={logo} alt="Clockwork Otter Foundry" ... />
    <h1 class="text-display max-w-3xl text-[var(--color-background)]">...</h1>
    <p class="text-body-large max-w-2xl text-[var(--color-background)] opacity-90">...</p>
    <Button href="/products" variant="primary">View Products</Button>
  </div>
</section>
```

Large, uniform vertical padding (`py-24 sm:py-32` — 96px/128px top and bottom) plus a single uniform `gap-6` (24px) between every child is what's producing the current spaciousness. `--header-height` is a fixed 72px (`BaseLayout.astro`'s `<Navigation>` above the hero).

**On "viewport-height-driven":** `BaseLayout.astro`'s `<body>` is `flex min-h-screen flex-col` with `<main class="flex-1">` — this is a standard sticky-footer pattern (keeps the footer pinned to the bottom on short pages) and should **not** be removed; it's not what's making the hero itself tall. Check specifically whether the hero *section* (not `body`/`main`) has, or effectively behaves like it has, any viewport-unit sizing (`min-h-screen`, `100vh`, or a flex-grow that stretches it) — if you find one, that's the actual thing to fix. If the hero's height today is purely `py-24 sm:py-32` + content (as it appears from the code above), then "make it content-driven" is already true structurally, and this phase is really just about *reducing* the padding values, not about removing a viewport-height mechanism that turns out not to exist — confirm which is the case and say so in your report rather than assuming.

## Scope

Adjust only vertical spacing in the hero. Specifically:

1. **Reduce the space above the logo** (top padding) — more than the reduction below.
2. **Moderately reduce the space below the CTA button** (bottom padding) — a smaller reduction than item 1, not symmetric.
3. **Slightly tighten the gap between the logo/wordmark and the headline specifically** — this is not a request to reduce every gap uniformly. The current `gap-6` applies the same 24px between all four children (logo→headline, headline→description, description→button); you'll likely need to break that into per-pair spacing (e.g. margin on the logo wrapper, or `space-y-*` utilities with an override on the first child) rather than one flat `gap-*` value, so you can tighten *just* the logo-to-headline gap while leaving the other two gaps as they are (not addressed by this phase).
4. **Target: ~650–700px of combined header+hero height at 1440×900.** Work out the actual math: read the real font-size/line-height values for `.text-display` and `.text-body-large` from `06-design-tokens.md`/`05-typography.md` (don't guess them), compute the intrinsic content height (logo + headline + description + button + your new gaps), then solve for top/bottom padding values that land the total (72px header + hero padding + hero content) in the 650–700px range. Show this math in your completion report.

**Explicitly do not change:** logo size (Phase 3e's dimensions stay exactly as they are), the White/reversed logo treatment itself, typography (font sizes, weights, line-heights untouched), or horizontal composition (`max-w-3xl`/`max-w-2xl`, centering, `--content-max-width`, the column layout). This phase is vertical spacing only.
