## Scope

### 1. Choose a self-hosting mechanism and verify its licensing

**Recommended approach, not a mandate:** the `@fontsource` npm package family (`@fontsource/bebas-neue`, `@fontsource/montserrat`, `@fontsource/inter`, `@fontsource/jetbrains-mono`) — each ships pre-built, per-weight CSS + WOFF2 files for exactly this self-hosting use case, resolves cleanly through Vite/Astro's asset pipeline with no manual file management, and (to Wolfgang's knowledge, **verify this yourself, don't trust it blind**) these four families are typically distributed under SIL OFL 1.1 (Bebas Neue, Montserrat, Inter) and Apache License 2.0 (JetBrains Mono) — both permit web self-hosting freely. **Actually check the license file each package installs with** and report what you found — this is exactly the "legally permitted for web use" requirement the brief calls out by name, don't just assert it.

If you find a concrete reason `@fontsource` doesn't fit well (e.g., a family/weight genuinely unavailable, a build issue), an equivalent alternative (manually sourced WOFF2 files with verified licensing, placed under `src/assets/fonts/` or `public/fonts/`) is fine — just document why you deviated and confirm the licensing check either way.

### 2. Import only the weights actually needed

Per the table in Project Context — don't import every weight a font family offers, only the ones this site's typography rules actually reference. If you determine JetBrains Mono 500 is genuinely unused, you can drop it (say so and why); if you're not certain, keep it rather than risk a silent regression.

### 3. Remove the Google Fonts CDN entirely

Delete the `<link rel="preconnect">` (both) and the `<link rel="stylesheet" href="https://fonts.googleapis.com/...">` from `BaseLayout.astro`. No residual reference to `fonts.googleapis.com` or `fonts.gstatic.com` should remain anywhere in `src/`.

### 4. Preserve `font-display: swap` behavior

The current Google Fonts URL requests `&display=swap` (avoids invisible text while fonts load). Confirm whatever self-hosting mechanism you use preserves equivalent behavior — `@fontsource` packages, if you use them, ship this by default in their CSS; verify it's actually present in what gets imported rather than assuming.

### 5. Zero visual change

This is the one thing to verify hardest. Same four families, same weights, same fallback stacks, same rendering. If you have any way to compare rendered output before/after (even a rough diff of computed `font-family`/`font-weight` values per element via the build output, since no live browser has reliably been available in this environment across prior phases — check if that's changed before assuming it's still blocked), do it.
