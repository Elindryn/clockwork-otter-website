## Goal

Move the Astro website — source code, its phase-prompt/result history, and its deployment config — out of `clockwork-otter-brand/website/` into this new standalone public repo, adjusting exactly the things that break when an Astro project stops being a subfolder of a monorepo and becomes a repo root of its own. Nothing else changes: same domain, same design tokens, same components, same content.

## Project Context

`clockwork-otter-brand` (private) has held the whole project as a monorepo: `docs/` and `assets/` (brand source-of-truth) alongside `website/` (the Astro implementation). Phases 1 through Deploy-1 were all built there. When the user went to configure GitHub Pages, GitHub required the source repository to be public — true for the Free plan regardless of whether Pages deploys via the legacy branch method or the Actions method this project uses. Making the whole monorepo public would also expose `docs/` (brand philosophy, voice/tone, internal standards) and `assets/` (every logo variant, including ones not yet released) — not just the built site. The user decided to split instead: keep `clockwork-otter-brand` private, move only the website into a new public repo.

That repo — `https://github.com/Elindryn/clockwork-otter-website` — already exists (confirmed via `gh api`: public, no commits, no default branch yet). This phase populates it.

**What doesn't need to change:** the domain (`clockworkotterfoundry.com`), the `CNAME` file's content, the Astro `site` config value, every design token/component/page — none of this depended on the old repo's folder structure. **What does need to change:** anything that referenced the old relative path from `website/` up to the brand docs (one level, `../docs/`) — that path is now wrong, since the website is a sibling of `clockwork-otter-brand`, not a child of it, so the correct relative path becomes two levels different: `../clockwork-otter-brand/docs/`. Also the deployment workflow's `path: website` input, since the Astro project is now at this new repo's root, not a subfolder.

Read `clockwork-otter-brand/website/CLAUDE.md` in full before starting — it's the file you're about to copy and adapt, and it documents every Standing Decision (logo, legal pages, font loading, logo contrast, deployment) that still applies here unchanged except for path references.

## Scope

### 1. Copy the website's content into this repo

From `../clockwork-otter-brand/website/`, copy into this repo's root:
- `src/`, `public/` (including `public/CNAME` and `public/favicon.svg` — unchanged, same domain/mark)
- `docs/Prompts/`, `docs/Results/` (the full phase history — Phase 1 through Deploy-1 — moves with the project; this preserves the lineage rather than starting undocumented)
- `package.json`, `package-lock.json`, `astro.config.mjs` (unchanged — `site` config stays correct as-is), `tsconfig.json`, `.gitignore`

**Do not copy:** `node_modules/`, `dist/`, `.astro/` (build artifacts/dependencies, regenerate via `npm ci`/`npm run build`), or `.claude/` (local session bookkeeping, not project content — let it regenerate fresh in the new repo).

### 2. Adapt `CLAUDE.md` for the new location

Copy `clockwork-otter-brand/website/CLAUDE.md` into this repo's root, then fix every path reference that assumed a monorepo structure:
- "Design System — Source of Truth" section: every `../docs/foundations/...`, `../docs/components/...`, `../docs/11-voice-and-tone.md`, `../docs/12-website-spec.md`, `../docs/standards/...` reference → prefix with `clockwork-otter-brand/` (i.e. `../clockwork-otter-brand/docs/foundations/...`, etc.).
- The "Logo assets" line references the old master PNG path and predates Phase 3b's SVG migration — while you're touching this section, feel free to correct it to reference the current SVGs (`../clockwork-otter-brand/assets/ProdHorizLogo.svg` etc.) instead of leaving a doubly-stale reference, but this is a minor cleanup, not the main point of this scope item.
- The Deployment Standing Decision paragraph: update the workflow's described location and the `path: website` detail — see Scope item 3.
- Everything else (Aesthetic, Tech Stack, Development Process, the 6 phase descriptions, Standing Decisions for Logo/Legal/Font-loading/Logo-contrast) is correct as-is and should carry over unchanged.

**Verify your own fix**: after editing, confirm every rewritten path actually resolves — e.g. `ls ../clockwork-otter-brand/docs/foundations/03-logo-system.md` should succeed from this repo's root. A silently-wrong relative path here is exactly the kind of thing that rots invisibly until a future phase tries to read it.

### 3. Deployment workflow

Copy `clockwork-otter-brand/.github/workflows/deploy.yml` into this repo at `.github/workflows/deploy.yml`. The Astro project is now at this repo's root, not a `website/` subfolder, so **remove the `path: website` input** from the `withastro/action` step entirely (its documented default is the repository root). Everything else in the workflow (trigger, permissions, concurrency, `actions/checkout`, `actions/deploy-pages`) is unaffected by the move and should carry over as-is — but do check current action versions again the way Deploy-1's own report did, rather than assuming the ones it pinned are still current.
