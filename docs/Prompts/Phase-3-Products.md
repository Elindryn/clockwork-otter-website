## Content Discipline

No real product names, descriptions, features, or screenshots exist anywhere in the design system yet. Do not invent any. Specifically:

- Product names: use the same bracketed convention as Phase 2 (e.g. `[Placeholder Product Name]`), applied consistently across the overview grid and the individual product page template.
- Descriptions, key features, and technical information: clearly-marked placeholder text following the same `[Placeholder — ...]` convention, per the 7-step sequence in `07-layout-system.md`. Do not write copy that reads as finished marketing or spec text.
- Screenshots: no real product screenshots exist. Use a clearly-labeled placeholder image area (e.g. a bordered/backgrounded `<div>` with `[Placeholder Screenshot]` text) rather than an invented or stock image.
- "Documentation link" and "Download or installation" steps in the 7-step sequence: point to real existing routes/labels only where one exists (`/documentation`), and use an honest placeholder (clearly non-functional, e.g. disabled-looking styling or `[Placeholder — download not yet available]`) where no real destination exists yet. Do not invent a download URL or fabricate availability.
- CTA button labels remain the one exception, same rule as Phase 2 — real, specific, action-describing labels for real destinations only.

4. **Home page product section replaced** — `src/pages/index.astro`'s existing 3 inline throwaway product `<div>` slots become 3 `ProductCard` instances, matching item 2's overview-page usage. 5. **Footer/Navigation integration** — confirm both still render correctly on the new/changed pages. No changes expected; if you find and fix a genuine regression, say so and explain it.
