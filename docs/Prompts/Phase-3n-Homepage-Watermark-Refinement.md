## Scope

### 1. Preserve the hero (verification only)

Confirm the hero's height, logo scale, headline typography, charcoal background, horizontal alignment, and overall composition are unchanged from Phase 3f/3h/3i's state. **No code change expected here.** Only touch the hero if you find something genuinely inconsistent that needs a minor spacing correction — if you do, explain exactly what and why before changing it.

### 2. "Creativity is the goal. Software is the craft." — more visual weight

In the "Tools Built With Purpose" section, give this closing line more presence than a plain bold sentence, restrained:

- More spacing above it than the current `mt-4`.
- Modestly stronger typography (e.g., a step up in size and/or weight from the current `font-semibold` — your call on the exact values, within "modest," not dramatic).
- Optionally, a short, thin horizontal Copper rule/accent associated with the line (e.g., a small `h-px` bar above or beside it, using `var(--color-brand-copper)`) — optional per the brief, include it only if it reads as restrained and confident, not decorative.

**Do not:** turn it into a giant pull-quote, center it, put it in a card/box, add quotation marks, add icons, or dramatically increase font size. The copy itself does not change.

### 3. "ANTIPHON" eyebrow label

Add a small label reading **ANTIPHON** directly above the Antiphon section's `<h2>Modern European e-invoicing, native to .NET.</h2>`. Requirements:

- Foundry Copper color (`var(--color-brand-copper)`).
- Small and restrained — a notably smaller size than the `<h2>` it sits above (e.g., in the `--text-sm`/`--text-xs` range), appropriate letter-spacing for a label/kicker treatment if you judge it improves legibility at that size (your call, keep it subtle).
- No large product card or panel — this is a single small text label, not a new visual container.
- The section's overall reading order stays: ANTIPHON → heading → body copy → closing statement → CTA.

Homepage only — do not add this to `src/pages/antiphon.astro` (the standalone product page). That page is out of scope for this phase; if you think it should get the same treatment for consistency, say so as a follow-up, don't do it now.

### 4. Reduce spacing between the two light sections (15–25%)

The current gap between "Tools Built With Purpose" and the Antiphon section is each section's independent `py-24` (96px) meeting at the boundary — 192px of combined space at that transition. Reduce this by **15–25%** (target combined transition space roughly 144–163px), without touching:
- The outer top padding of "Tools Built With Purpose" (space below the hero).
- The outer bottom padding of the Antiphon section (space above the footer).
- The reading-column width (`--reading-max-width` stays exactly as-is).

Show your math. Use Tailwind's existing spacing scale (e.g., `py-24` → `py-20` on the two inner edges is a clean, token-scale-respecting 16.7% reduction landing at 160px combined — a reasonable candidate, but verify and choose the value that actually fits the 15–25% target rather than assuming this one is right). Don't invent an arbitrary pixel value outside the scale unless the scale genuinely can't hit the target band — if that happens, say so.

### 5. Copper watermark

Add one large, decorative, heavily-cropped Copper watermark of the otter/gear **mark only** (not the wordmark) to the light content area, positioned around the transition between the two sections from Scope item 4.

**Visual spec:**
- Roughly 500–700px diameter.
- Positioned on the far right, deliberately drifting off-screen — roughly 25–40% of it extending past the right edge.
- Vertically centered approximately on the boundary between the two sections.
- Foundry Copper color, via the CSS mask technique described in Project Context (recolor the existing flat black mark SVG, don't touch the source file).
- Opacity target ~4%, acceptable range 3–5%. If it's noticeable before the text is, it's too strong — err toward the low end if unsure.
- The full gear should **not** read as neatly centered/complete — cropping against the viewport edge is the point.

**Implementation:**
- A reasonable approach: wrap the two light sections (or introduce a thin non-content wrapper spanning their boundary) in a `position: relative` container with `overflow-x: clip` (or `hidden`) so the off-screen portion of the mark never causes horizontal page scroll, then absolutely position the watermark element inside it. This is a structural/positioning-only wrapper, not a new visible section — verify this doesn't disturb the actual visible page structure.
- Use Astro's `define:vars` (or an equivalent clean mechanism) to pass the imported SVG's resolved URL into a scoped `<style>` block's `mask-image`/`-webkit-mask-image`, with `background-color: var(--color-brand-copper)` supplying the color and `mask-size: contain; mask-repeat: no-repeat` (plus `-webkit-` prefixes) controlling the fit. If you find a cleaner equivalent technique, use it — this is a suggestion, not a mandate.
- `pointer-events: none`, `aria-hidden="true"`, no semantic role, and confirm it sits behind all real content (verify visually/structurally, don't just assume the DOM order + transparent section backgrounds handle it — check).
- The content (headings, body copy, CTA) must remain fully readable with the watermark removed entirely — i.e., it's a pure visual addition with zero layout dependency.

**Mobile:** do not apply the desktop treatment at narrow widths. Either greatly reduce/reposition it, or hide it entirely — prefer hiding if a reduced version would still clutter or threaten readability on a narrow viewport. Your call, state which you chose and why.

### 6. Logo-usage confirmation (no action expected)
