### 2. Inter weight 700 gap

`src/pages/index.astro`'s "Creativity is the goal. Software is the craft." line uses `font-bold` (Inter 700), but only weights 400/500/600 are self-hosted (Phase 5) — the browser has been synthesizing/substituting a fake bold this whole time. Two ways to close this, your call:

- **Import the real weight**: add Inter 700 via the same `@fontsource/inter` mechanism Phase 5 already established (check `src/styles/global.css` for the existing per-weight import pattern and add the 700 line alongside them).
- **Change the utility class**: drop to `font-semibold` (600, already loaded) if you judge the visual difference is negligible and not worth another font file.

Whichever you pick, state which and why. If you import the real weight, confirm in the built output that it's actually being used (inspect the compiled `@font-face` rules and the element's computed weight, don't just assume the import fixed it).

### 3. Footer link touch targets

`src/components/Footer.astro`'s links currently use `px-2 py-2` (Phase 7), which improved but didn't fully reach the ~44×44px accessibility guideline (approximately 38px tall today). Increase the vertical padding (Phase 7's own estimate: `py-3`+ should clear 44px, but verify the actual computed height rather than trusting that estimate) enough to reach 44px, and look at whether the footer's overall vertical rhythm (the `py-12` on the outer container, the `gap-6`/`gap-y-2` spacing) needs a small adjustment to accommodate the taller links without looking cramped or unbalanced — this was explicitly flagged by Phase 7 as needing more than a padding-only patch, so don't just bump the padding number and call it done without checking the visual result reads fine.

### 4. Header logo too small on mobile — REVISES Phase 7's calculated conclusion, direction reversed

**This item replaces what Wolfgang originally scoped here.** Phase 7 calculated that the header logo (currently `width={217} height={50}` at every breakpoint, no mobile-specific sizing exists yet) leaves a "tight but passing" ~11px margin at the 320px viewport, and the original version of this prompt asked for the logo to be made *smaller* on mobile to widen that margin. **The user has now actually looked at the live, deployed site on a real phone and reports the opposite problem: the header logo looks far too small on mobile at its current size.** Do not shrink it. If anything, it needs to grow.

This creates a real, worth-stating-explicitly tension: growing the logo eats into the same tight margin Phase 7 measured. Resolve it in this order:

1. **Increase the header logo's size specifically on mobile/narrow viewports** (below the `md` breakpoint) — desktop (`md:` and up) stays exactly `217×50`, untouched, since only mobile was flagged. Pick a size that reads as clearly, comfortably larger — not a token bump. As a starting reference point, something in the ~250–280px width range (proportionally ~58–65px tall, aspect ratio 4.34:1 preserved) is a reasonable target to evaluate against, but use your own judgment on what actually looks right at real mobile widths rather than treating that range as a hard spec.
2. **Reclaim horizontal room to fit it**, since the desktop-size logo was already using ~95% of the available width at exactly 320px. Reduce the header's horizontal padding on mobile only (currently `px-6` = 24px each side; consider `px-4` = 16px each side below `md`, reverting to `px-6` at `md:` and up) before considering anything else.
3. **Treat 320px (the original iPhone SE/5-class width) as a legacy edge case, not the binding constraint** — most real devices today are 375px and up. If a meaningfully larger logo doesn't comfortably fit at exactly 320px even after reclaiming padding, that's an acceptable trade-off; show the arithmetic at both 320px and 375px+ and state plainly how each one turns out, rather than silently picking a size that happens to still fit 320px and undershooting what actually looks right on real devices.
4. Do **not** shrink the mobile toggle button below its current 44×44px — that's an accessibility floor from Phase 7, not adjustable here.

Verify the taller/wider logo still centers cleanly within the unchanged 72px header height (`--navigation-height`) — there's real headroom (72px − ~65px logo ≈ 7px total), confirm it actually looks centered, not just that it numerically fits.
