## Scope

### 1. Astro site config

Add `site: 'https://clockworkotterfoundry.com'` to `website/astro.config.mjs`. Do not add a `base` — see Project Context for why.

### 2. Custom domain file

Create `website/public/CNAME` containing exactly one line: `clockworkotterfoundry.com` (no protocol, no trailing slash, no `www`). Astro copies `public/` contents verbatim into `dist/`, so this becomes `dist/CNAME` and is uploaded as part of the Pages deployment artifact — this is what makes the custom domain persist across every future deploy without needing to be re-entered in GitHub's settings each time.

### 3. GitHub Actions workflow

Create the workflow at `../.github/workflows/deploy.yml` — **note this is one level above `website/`, at the confirmed git root** (see Project Context), since every prior Clockwork prompt scoped changes to inside `website/` only and this one doesn't.

**Use the official `withastro/action`** (maintained by the Astro team), not a hand-rolled multi-step workflow — this is GitHub's own suggested starter workflow for Astro projects and is simpler to get right than composing `configure-pages`/`upload-pages-artifact` manually. The one detail that matters and is easy to get wrong: **this repo's Astro project is not at the git root, it's in `website/`**, so the action's `path` input must be set explicitly — GitHub's auto-suggested version of this workflow assumes root and will fail without it.

```yaml
name: Deploy to GitHub Pages

on:
  push:
    branches: [main]
  workflow_dispatch:

permissions:
  contents: read
  pages: write
  id-token: write

concurrency:
  group: "pages"
  cancel-in-progress: false

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - name: Checkout your repository using git
        uses: actions/checkout@v4
      - name: Install, build, and upload your site
        uses: withastro/action@v3
        with:
          path: website

  deploy:
    needs: build
    runs-on: ubuntu-latest
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    steps:
      - name: Deploy to GitHub Pages
        id: deployment
        uses: actions/deploy-pages@v4
```

Treat this as a starting point, not gospel — check `withastro/action`'s current README for its actual accepted inputs and the current recommended action versions before committing to these exact pins, since third-party action versions drift. Confirm the `path: website` input specifically, since that's the one thing certain to break silently if omitted (`npm ci`/`npm run build` would run against the repo root, which has no `package.json`).
