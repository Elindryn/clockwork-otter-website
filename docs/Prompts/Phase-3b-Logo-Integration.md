## Project Context

Phase 1 (Foundation, closed 2026-08-07) shipped with the only logo asset that existed at the time: `src/assets/images/logo/clockwork-otter-logo-primary.png`, a square, vertically-stacked lockup on an opaque white background. Phase 1's own review flagged two problems with it that were never fixed, only worked around: (1) the opaque white background reads as a white patch on the Foundry Charcoal nav bar, and (2) the wordmark is set in a serif face rather than the spec'd Bebas Neue. Phase 2 (Home Page, approved 2026-08-07) deliberately omitted the logo from the hero entirely rather than reproduce problem (1) at a larger scale — the user explicitly rejected a white-card backdrop as a workaround and deferred the whole question until a proper logo variant existed.

That variant now exists. Three new SVGs landed 2026-08-09 in `../clockwork-otter-brand/assets/` (the parent brand repo, read-only from this repository):

- `ProdHorizLogo.svg` — symbol left, wordmark right (`viewBox="0 0 1000 250"`, 4:1 aspect ratio). Intended for the nav.
- `ProdVertLogo.svg` — symbol above, wordmark below (`viewBox="0 0 862.78498 1084.263"`, tall). Intended for the hero.
- `ProdMarkLogo.svg` — symbol only, no wordmark (`viewBox="0 0 250 250"`, square). Intended for the favicon and other small placements.

**Important finding from Wolfgang's inspection (XML/path inspection only — no rendering tool was available, this was not a visual check):** all three files use exactly two fill colors, `#000000` and `#ffffff` — no brand copper (`#B87333`) or Foundry Charcoal (`#2B2B2B`). The mark specifically is a black gear-shaped silhouette with a white otter face/details drawn on top, plus a few small black details (eye, ear, some whiskers) layered back on top of the white — a self-contained two-tone badge, not a flat single-color mark you could trivially recolor per background. Switching from PNG to SVG structurally fixes problem (1) above (SVGs here have transparent backgrounds, not opaque rectangles), but whether the black gear silhouette itself reads clearly against Foundry Charcoal is a genuine open question this inspection could not answer. Verifying it live is this phase's most important verification step — see below.

Relevant files to read before starting:
- `CLAUDE.md` (this repo's root) — Standing Decisions section
- `../docs/foundations/03-logo-system.md` — Logo Variants (names these exact three shapes: Primary Full Logo, Symbol Mark, Horizontal Variant), Clear Space (25% of gear diameter minimum, every side), Minimum Size (180px recommended minimum digital width for the full logo), Background Usage, Incorrect Logo Usage (forbids altering, recoloring, outlining, or adding effects to the canonical artwork — this phase integrates the SVGs as delivered, it does not edit them)
- `../docs/foundations/04-color-system.md` — token names (`--color-brand-charcoal`, etc.)
- `src/components/Navigation.astro` — current PNG import and 52×52 render in the charcoal nav bar
- `src/pages/index.astro` — hero section (charcoal background, currently H1 + paragraph + one `Button`, no logo)
- `src/layouts/BaseLayout.astro` — no favicon link exists here at all currently; there is no `public/` directory either

## Scope

### 1. Bring the new assets into this repository

Copy the three SVGs from `../clockwork-otter-brand/assets/` into `src/assets/images/logo/`, renamed to match this repo's existing naming convention (e.g. `clockwork-otter-logo-horizontal.svg`, `clockwork-otter-logo-vertical.svg`, `clockwork-otter-logo-mark.svg` — adjust to whatever convention you find already in use). Copy only — do not alter the source files' markup, colors, or structure. The parent brand repo's `assets/` directory itself is read-only from here; only copy out of it, never write into it.

### 2. Navigation — swap PNG for the horizontal SVG

Replace the `clockwork-otter-logo-primary.png` import in `src/components/Navigation.astro` with the new horizontal SVG. The old asset was rendered square at 52×52; the new one is a 4:1 horizontal lockup, so the sizing needs to change to fit its actual proportions rather than being forced into the old square footprint. Respect the 25%-of-gear-diameter clear space and the 180px recommended minimum digital width from `03-logo-system.md` — use judgment on how these translate to a fixed-height nav bar, and explain your sizing choice in the completion report.

### 3. Hero — add the vertical SVG

Add the vertical lockup to the hero section in `src/pages/index.astro`, above the H1, respecting the same clear-space guidance. Size it so it doesn't dominate the hero on mobile — this is new visual weight in a section that previously had none, so check the small-viewport case specifically (both in code and in the live browser check below).

### 4. Favicon — new functionality, not a swap

This repository currently has no favicon at all — no `public/` directory, no `<link rel="icon">` anywhere in `BaseLayout.astro`. Add one using the mark-only SVG, following standard Astro convention (typically `public/favicon.svg` referenced via `<link rel="icon" type="image/svg+xml" href="/favicon.svg">` in `BaseLayout.astro`'s `<head>`).

### 5. Retire the old asset

Once the above are in place, `grep` the repository to confirm nothing still references `clockwork-otter-logo-primary.png`, then delete it.

### 6. Live legibility check — do not skip

Run the dev server (`npm run dev`) and actually look at the nav and hero logos against Foundry Charcoal. This has been deferred across Phases 1, 2, and 3 for environment reasons (sandboxed session, no GUI, slow `/mnt/c` startup) — if the same constraints apply here, say so explicitly and explain what you tried, but make a real attempt first; this phase exists specifically to answer a legibility question static HTML inspection cannot resolve.

If the logos are genuinely hard to read against Foundry Charcoal: **do not invent a workaround.** Do not add a white card, tinted backdrop, or any other visual treatment behind the logo — the user explicitly rejected exactly that workaround during Phase 2's review of this same underlying problem. Stop, document exactly what you observed (which element, at what size, why it's hard to read), and report it as an open item for Wolfgang/the user to resolve. It is a legitimate, expected outcome of this phase to conclude "the new assets fix the transparency problem but contrast is still marginal" — that is useful information, not a failure to fix silently.
