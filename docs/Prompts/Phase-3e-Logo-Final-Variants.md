## Project Context

**What changed:** the parent brand repo's `assets/` now has 6 new flat SVGs (in place of/alongside the old 3 two-tone ones): `ProdMarkWhiteLogo.svg`, `ProdMarkBlackLogo.svg`, `ProdVertWhiteLogo.svg`, `ProdVertBlackLogo.svg`, `ProdHorizWhiteLogo.svg`, `ProdHorizBlackLogo.svg`. Wolfgang inspected all of them directly before writing this prompt: each file contains **both** a white and a dark version of the same shape internally (Inkscape layers toggled via `style="display:none"` / `"display:inline"`, labeled `White Gear`/`Dark Gear` and `White Text`/`Dark Text`), but only one is actually visible in each file — the filename tells you which. Each visible shape is a **single flat fill**, no internal two-tone layering like the old artwork (no separate white-face-on-black-gear construction) — this is what makes a clean color-only swap actually work now, unlike Phase 3d's failed attempt on the old files.

The Mark files (`ProdMarkWhiteLogo.svg`/`ProdMarkBlackLogo.svg`) have their Text layer entirely hidden (`display:none` on the whole group) — symbol-only, consistent with the mark's established purpose (favicon, small placements). The Horiz and Vert files show both the gear/symbol and the wordmark together, matching their established Nav/Hero roles.

**Why this fully resolves the saga, not just another workaround:** Phase 2's rejected white-card idea and Phase 3c's white-box fix were both compensating for the *artwork itself* lacking a background-appropriate version. This is the artwork having one now — literally what `03-logo-system.md`'s own Logo Variants section calls for (Reversed Variant: white logo for dark backgrounds). No box, no recolor trick, no compensating layout — just the right asset for the right background, same as Phase 1's PNG did on light backgrounds before any of this started.

### 2. Nav — remove the box, use the White horizontal variant

Remove Phase 3c's white-background/copper-border/radius wrapper from `Navigation.astro` entirely. Render the **White** horizontal logo directly, transparent background, no container styling beyond normal layout. Since there's no box eating into the 72px header anymore, you can very likely return to Phase 3b's original 180×45 sizing (it fit cleanly within the header's ~70px content height with real margin, per Phase 3b's own clear-space math) — confirm this still holds rather than assuming.

### 3. Hero — remove the box, use the White vertical variant

Same removal in `index.astro`'s hero section. Render the **White** vertical logo, transparent background, at Phase 3b's original sizes (160px mobile / 224px `sm:`+).

### 4. Favicon — your call, White or Black variant of the mark

The current favicon uses the old two-tone mark. Browser tab chrome is usually light by default, so the **Black** mark variant is the safer default — but this is low-stakes (small, browser-chrome context, never flagged as a contrast problem) and your judgment is fine here. Say which you picked and why.

### 5. Verify contrast, but this should be a formality now

Use the rasterize-and-measure technique from Phases 3b/3c if a live browser still isn't available (try a real browser first — environments have varied run to run in this project). Confirm the White logo's flat fill against Foundry Charcoal clears 3:1 by a wide margin — expect something close to the previous pure-white measurement (14.16:1), since this is now a genuinely flat white shape, not a mixed two-tone mark. This is confirmation, not the open question Phase 3d was investigating — if it somehow doesn't pass, that's a real surprise worth flagging clearly, not something to quietly work around.
