### 2. Header logo size

Increase the header logo (`src/components/Navigation.astro`) by **10–15%** from its current `width={194} height={45}` (aspect ratio ≈ 4.31:1) — e.g. ~213–223px wide, ~49–52px tall, maintaining aspect ratio exactly. `--navigation-height` (currently 72px, via `--header-height`) must **not** materially increase — confirm the larger logo still fits within the existing header height with its current vertical padding/centering, at all breakpoints. Preserve the current reversed-white logo treatment (Phase 3e) — swap only the `width`/`height` props, not the asset or its color handling.

### 3. Primary CTA color

Once `CLOCKWORK-BRAND1` has landed (see How to Execute), update `src/styles/tokens.css`'s `## Actions` block (and the `## Buttons` component-token block just below it, `--button-primary-background`/`--button-primary-text`/etc.) to mirror the canonical file exactly. `Button.astro` currently has **no `:active` state and no focus-visible styling at all** beyond the browser default — a real gap independent of the color change, but one the eval explicitly requires be closed as part of this pass ("normal, hover, active, and keyboard-focus states meet accessibility requirements"). Add both:

- An active-state background (same `color-mix()` pattern as the existing hover token, e.g. mixing further toward black than the hover value).
- A visible focus-visible outline, using whatever `04-color-system.md`'s Focus Indicators section specifies once `CLOCKWORK-BRAND1` updates it (it may still be Steel Blue, confirmed against the new Copper button background, or something else — read the updated doc, don't assume it's unchanged).

Verify all four states (normal, hover, active, focus) against both the button's own background and, for focus, against the page background behind it, with real contrast numbers — don't assert compliance without showing it. Use the existing token/`color-mix()` pattern throughout; do not introduce a new hardcoded hex anywhere in this repo.

### 4. Primary CTA text and destination

Home page hero CTA (`src/pages/index.astro`): change the button label from `View Products` to **`Explore Antiphon`**, and its `href` from `/products` to the new Antiphon product page path (see Scope item 5 for the exact path — keep them consistent).

### 5. V1 navigation and the product-structure fix it requires

**Navigation** (`src/components/Navigation.astro`): replace the `Products` link with **`Antiphon`**, linking directly to the Antiphon product page. Resulting order: `Home | Antiphon | Documentation | About | Contact`.

**Footer** (`src/components/Footer.astro`): it has its own separate `Products` link pointing at `/products`. The eval's spec only names the primary nav, but leaving a stale `/products` link in the footer once the primary nav no longer offers one would create an orphaned page reachable only from the footer, advertising three fake products. Apply the same fix here for consistency — relabel/relink it to match the primary nav's Antiphon link. If you disagree this is in scope, leave it and flag it explicitly in your report instead of silently skipping it.

**Do not create a `/products` landing page** — there's exactly one public product; a landing page over one item is unnecessary (this is explicit in the eval). Concretely:

- Move/rename `src/pages/products/example-product.astro` → `src/pages/products/antiphon.astro`. Point the nav, footer, and hero CTA at this exact path.
- Delete `src/pages/products/index.astro` (the `/products` overview page) — no longer linked from anywhere once the above lands, and the eval explicitly says not to have one.
- Replace the placeholder content in the moved page with real, verified facts about Antiphon — do not invent anything beyond what's given here:
  - **Product name:** Antiphon
  - **One-sentence value statement:** "Generate, validate, and convert EU-mandated e-invoice formats — XRechnung, Factur-X/ZUGFeRD, Peppol BIS UBL — from .NET, without a Java sidecar."
  - **Key features** (restate or lightly paraphrase; do not add claims beyond these): EN 16931-compliant validation, generation, and conversion across UBL and CII formats; offline license enforcement with no telemetry and no network calls; Factur-X/ZUGFeRD PDF/A-3 embedding and extraction.
  - **Distribution:** available via NuGet and directly through Clockwork Otter Foundry (once launched).
  - **Download/pricing/screenshot sections:** keep the existing placeholder page's honest "not yet available" pattern — Antiphon has not launched, has no price, and has no public screenshot yet. Do not fabricate any of these.
  - **Documentation link:** the existing "View Documentation" button pointing at `/documentation` can stay as-is.
- Home page's "Product overview" section (`src/pages/index.astro`): currently renders 3 identical placeholder `ProductCard`s all linking to the same URL. Replace with a single `ProductCard` for Antiphon (real name/description per above, same href as the nav), and adjust the surrounding grid/layout so a single card doesn't look like a broken 3-column grid (your call on the exact treatment — could be a narrower single-column presentation, or something else consistent with the design system; explain your choice).
