## Task Description

Build the underlying website framework using Astro with Tailwind CSS. This is architectural scaffolding, not content. Every visual decision (color, type, spacing, radius) must trace back to a token defined in `06-design-tokens.md` — do not hard-code hex values, pixel spacing, or arbitrary Tailwind utility values that bypass the token system.

Configure Tailwind's theme (`tailwind.config`) to consume the design tokens rather than Tailwind's default palette/spacing/typography scale. Prefer CSS custom properties as the source of truth (per the token hierarchy in `06-design-tokens.md`: raw token → semantic token → component token), with Tailwind config referencing those custom properties where practical.

## Exact Scope

1. **Project structure** — standard Astro project layout (`src/`, `src/layouts/`, `src/components/`, `src/pages/`, `public/`), with a clear, documented convention for where layouts, components, and page templates live.
2. **Build configuration** — Astro config, Tailwind config, package.json scripts (dev/build/preview), TypeScript config if using `.astro`/`.ts` with type checking.
3. **Design token implementation** — CSS custom properties file implementing the full token set from `06-design-tokens.md` (color, typography, font-weight, font-size, line-height, spacing, radius, border, shadow, motion, z-index, layout, breakpoints). Wire Tailwind's theme to these tokens.
4. **Theme implementation** — apply tokens globally (background, surface, text-primary/secondary, brand colors) per the page color strategy in `04-color-system.md`.
5. **Font loading** — Bebas Neue (400), Montserrat (600, 700), Inter (400, 500, 600), JetBrains Mono (400, 500) — only these weights, per `05-typography.md`'s Font Loading section. Self-host or use Google Fonts with preconnect; avoid layout shift.
6. **Global typography** — heading hierarchy (Display, H1–H4), body/body-large/small-text, code text, all mapped to the correct typeface per `05-typography.md`.
7. **Global layout / responsive framework** — content max-width (1200px), reading width guidance (700–800px), 12-column grid, responsive breakpoints from the tokens.
8. **Navigation component** — top nav per `07-layout-system.md`: Home, Products, Documentation, About, Contact. Foundry Charcoal background, Steel Blue hover, Copper active-page indicator, thin Copper bottom divider. Keyboard-navigable, visible focus states.
9. **Footer component** — per `07-layout-system.md`: copyright, product links, documentation, privacy policy, terms of service, contact. Visually understated.
10. **Basic page templates** — placeholder-only pages for Home, Products, Documentation, About, Contact, each using the shared layout/nav/footer. Simple placeholder headings (e.g. "Home — placeholder") — no marketing content, no invented copy, no Lorem Ipsum.
11. **Asset organization** — place the existing logo PNG under a sensible `public/` or `src/assets/` path; establish (but do not populate beyond what exists) the convention for where future logo variants/favicons will live per `03-logo-system.md`'s naming convention.
