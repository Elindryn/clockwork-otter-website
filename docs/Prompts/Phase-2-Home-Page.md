## Content Discipline

No real product names, descriptions, or marketing copy exist anywhere in the design system yet — Phase 3 (Products) hasn't defined the product catalog. Do not invent any. Specifically:

- **Hero headline:** use the company's actual documented motto, verbatim, from `01-brand-philosophy.md`: *"Crafted with precision. Designed for creativity."* This is real brand content, not invented copy.
- **Hero supporting line, introductory content, and product-overview descriptions:** clearly-marked placeholder text, following Phase 1's convention (e.g. `[Placeholder — one-sentence description of Clockwork Otter Foundry]`) so it's unmistakable as non-final when viewed in a browser. Do not write copy that reads as finished marketing text.
- **Product overview section:** build 2–3 placeholder product slots (`[Placeholder Product Name]` + one placeholder line each) — structural only. Do not invent plausible-sounding product names or features.
- **CTA button labels are the exception** — these describe real actions to real existing routes, so they should be real, specific labels (e.g. "View Products" → `/products`, "Contact Us" → `/contact`), per the voice/tone button rules. Not placeholder, not vague ("Submit", "Click Here", "Learn More").

## Exact Scope

1. **Hero section** — headline (the motto, verbatim), one placeholder supporting sentence, one primary CTA button. Generous whitespace per `07-layout-system.md`'s Hero Sections guidance. The existing logo PNG may appear at hero scale (native vertical proportions are fine here per the Standing Decision above) — optional, your call whether it strengthens or clutters the section.
2. **Introductory content section** — a short section beneath the hero, placeholder body copy, real heading structure (H2), left-aligned per default alignment rules.
3. **Product overview section** — 2–3 placeholder product slots in a responsive grid/row, each with a placeholder name, one placeholder description line, and a "Learn more"-style link. **Do not build a formal reusable `ProductCard` component** — that's Phase 3's explicit job, once real products and Phase 3's product-page requirements exist. Use minimal, honest inline markup for this section only; Phase 3 will very likely replace it.
4. **Call-to-action / Button component** — build one reusable component (e.g. `src/components/Button.astro`) with primary and secondary variants per `04-color-system.md`'s Buttons section (primary: Steel Blue background, white text, rounded corners, accessible hover/focus state; secondary: transparent background, Copper border and text, used sparingly). Use it for the hero CTA and any other CTA on this page. This is the reusable asset Phase 2 is expected to produce — later phases should reuse it rather than hand-rolling new button markup.
5. **Footer integration** — confirm `Footer.astro` (built in Phase 1) renders correctly on the reworked Home page. No changes expected; if you do find and fix a genuine regression, say so and explain it in the completion report.
